# 01 · 技术方案与依赖环境

## 1. 需求拆解

| 需求 | 落地方式 |
|---|---|
| 识别当前游戏界面状态 | 模板匹配（固定元素）+ OCR（动态文本）+ 前台包名校验 |
| 规划并执行操作策略 | 界面状态机：每个界面绑定一个处理器（点击/选择/等待） |
| 模拟点击或滑动交互 | ADB `input tap/swipe`，坐标随机抖动、间隔随机 |
| 遇不确定决策主动提问 | `core/asker.py` 统一提问接口，附截图 + 选项 + 推荐 |
| 资源系统化沉淀 | `config/*.yaml`（坐标/关键词）+ `assets/templates/`（模板） |
| 稳定 + 容错重试 | 见 README §6 |

---

## 2. 技术选型与理由

### 2.1 为什么用 ADB 而不是 uiautomator2 / Airtest

| 方案 | 评价 |
|---|---|
| **裸 ADB（本项目采用）** | 游戏是 Canvas/Unity 渲染，**无无障碍节点**。ADB 直接发触摸事件，最贴近真实人工操作，依赖最少、最稳。雷电自带 `adb.exe`，无需额外安装。 |
| uiautomator2 | 依赖无障碍服务，对游戏内元素**完全无效**；且需在模拟器内装 agent，增加不确定性。 |
| Airtest | 图像识别封装不错，但引入 Poco/Unity 依赖较重，且提问交互、配置化不如自建灵活。 |

> 结论：**ADB 提供手和眼，自建 Python 层做识别与决策**，是本场景最稳的组合。

### 2.2 为什么模板匹配 + OCR 混用

| 场景 | 方案 | 理由 |
|---|---|---|
| 固定按钮、图标、界面锚点 | **模板匹配** | 分辨率锁定 1920×1080，准确率极高，单次 5–20ms |
| 里程数、进度、结算文案 | **OCR（rapidocr）** | 文本内容动态变化，模板无法覆盖 |

实测证据（登录页截图）：OCR 对普通文字识别置信度 0.97–1.00，但把美术字体 logo「名将杀」误读为「名特茶」（0.59）。**说明按钮/logo 必须走模板匹配**。

### 2.3 为什么选 rapidocr-onnxruntime

* 离线可用，**纯 pip 安装**，不需额外装 tesseract 二进制及其 `chi_sim` 语言包
* 自带中英文识别模型，对中文美术字体明显优于 tesseract
* onnxruntime CPU 推理，整屏约 0.3–0.8s（首次含模型加载 ~8s）；裁剪区域可进一步提速

## 3. 架构分层

```
┌──────────────────────────────────────────────────────────┐
│ run.py  统一入口                                          │
│   selfcheck / capture / analyze / observe / run          │
└───────────────┬──────────────────────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────────┐
│ core/engine.py   主循环：抓屏 → 判定 → 执行 → 休眠        │
│   · 卡死检测  · 逐轮异常隔离  · 异常截图归档  · dry-run   │
└───┬───────────────┬──────────────────┬───────────────────┘
    │               │                  │
┌───▼────────┐ ┌────▼─────────┐ ┌──────▼──────────────┐
│ game/      │ │ vision/      │ │ core/asker.py       │
│ screen.py  │ │ matcher.py   │ │ 暂停提问（cli/弹窗） │
│ 界面状态机  │ │ ocr.py       │ │ 截图+选项+推荐+记录  │
│ policy.py  │ │ annotate.py  │ └─────────────────────┘
│ 决策打分    │ └──────────────┘
└───┬────────┘        │
    │                 │
┌───▼─────────────────▼────────────────────────────────────┐
│ devices/adb.py   ADB 控制层                              │
│   截图(exec-out) / tap / swipe / long_press / keyevent   │
│   设备自检 · 自动重连 · 命令超时                          │
└───────────────┬──────────────────────────────────────────┘
                │
        ┌───────▼────────┐
        │ 雷电9 1920x1080 │
        │ com.ztgame.mjs  │
        └────────────────┘
```

**分层原则**：`devices` 只负责"手脚"，`vision` 只负责"眼睛"，`game` 负责"该干什么"，`core` 负责"怎么安全地循环"。各层不互相越权，便于单独替换（例如日后换 OCR 引擎只改 `vision/ocr.py`）。

## 4. 依赖环境

### 4.1 实测环境

| 项 | 实测值 |
|---|---|
| 操作系统 | Windows（win32） |
| 模拟器 | 雷电 9（使用模拟器自带 adb） |
| ADB | 模拟器自带 adb，或系统 PATH 中的 `adb` |
| 设备序列号 | `emulator-5554` |
| Android 版本 | 9 |
| 分辨率 / DPI | 1920×1080 / 280 |
| 游戏包名 | `com.ztgame.mjs` |
| 前台 Activity | 主界面 `com.giant.ztgame.GameActivity` |
| Python | Python 3.11+（项目根目录 `.venv`） |

### 4.2 Python 依赖

| 包 | 来源 | 版本 |
|---|---|---|
| opencv-python | anaconda 自带 | 4.13.0 |
| numpy | anaconda 自带 | 1.26.4 |
| Pillow | anaconda 自带 | 12.2.0 |
| PyYAML / tkinter / requests | anaconda 自带 | — |
| rapidocr-onnxruntime | 本项目安装 | 1.4.4 |
| onnxruntime | 随 rapidocr 安装 | 1.30.0 |

### 4.3 隔离策略

采用 `venv --system-site-packages`：**继承** anaconda 已有的 OpenCV/NumPy/Pillow（避免重复下载数百 MB），**只把 OCR 新增依赖装进项目自己的 `.venv`**，不污染主环境。

```bash
"python" -m venv --system-site-packages .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
```

## 5. 运行方式

全部命令经由 `run.py` 统一入口，见 README §3。

**关键设计**：`analyze` / `observe` 两个子命令**完全不点击游戏**，是标定与调试阶段的安全模式。只有在资源标定完毕、离线验证通过后，才建议执行 `run`。

## 6. 稳定性设计要点

1. **坐标与分辨率解耦**：`config/coords.yaml` 一律按 1920×1080 记录，运行时按实际分辨率等比缩放（`common/utils.scale_point`）。
2. **判定优先级排序**：特征最明确的界面（如结算弹窗）优先判定，通用兜底放最后，降低误判。
3. **未知界面绝不瞎点**：`handle_unknown` 只做三件事——存档截图、记录日志、提问用户。
4. **点击后校验**：处理器返回后重新抓屏，由下一轮循环确认界面是否已切换；若长时间未切换则触发卡死检测。
5. **人工化节奏**：随机点击间隔 + 坐标抖动，避免机械节奏。

## 7. 已知风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 游戏版本更新导致 UI 变化 | 坐标/模板失效 | 判定失败自动转 `unknown` 并提问，不会误点；重跑标定流程即可 |
| 美术字体 OCR 误识别 | 文本判定出错 | 关键词取短词 + 高阈值 + 限定区域；关键按钮用模板 |
| 模拟器渲染偶发差异 | 模板匹配分数下降 | 多尺度搜索（0.92–1.08）+ 可调阈值 |
| 战斗动画时长不定 | 轮询空转 | 进入 `battle` 状态后降低轮询频率 |
