# 04 · OCR 关键词与规则

## 1. 引擎与参数

| 项 | 值 |
|---|---|
| 引擎 | `rapidocr-onnxruntime` 1.4.4（离线，CPU 推理） |
| 最低置信度 | `config/settings.yaml → ocr.min_score`，默认 **0.5** |
| 文本归一化 | 开启：NFKC（全角→半角）+ 去除所有空白 |
| 整屏耗时 | 首次约 8s（含模型加载），之后约 **0.3–0.8s** |
| 区域裁剪 | 支持，可显著提速并降低误判 |

---

## 2. 使用原则

| 原则 | 说明 |
|---|---|
| **按钮/图标不用 OCR** | 美术字体识别不稳（实测：「名将杀」→「名特茶」，置信度仅 0.59）。按钮一律用模板匹配。 |
| **OCR 只处理普通文本与数值** | 里程数、进度、结算文案、弹窗提示等 |
| **短词 + 高阈值 + 限定区域** | 关键词越短越稳（如「胜利」而非「战斗胜利，获得奖励」）；限定区域避免背景干扰 |
| **数值用正则抽取** | 而非整行文本比对 |

---

## 3. 规则格式（config/ocr_rules.yaml）

```yaml
rules:
  <屏幕标识>:
    <字段名>:
      region: [x1, y1, x2, y2]     # 识别区域（基准分辨率），省略=全屏
      keywords: ["胜利", "通关"]    # 任一命中即算通过
      all_keywords: ["里程", "奖励"] # 必须全部命中（可选）
      exclude: ["失败"]             # 命中任一则否决（可选）
      regex: "里程\\s*(\\d+)"       # 数值抽取（可选）
      min_score: 0.6               # 覆盖全局阈值（可选）
      desc: "用途说明"
```

判定逻辑（`src/vision/ocr.py::OCREngine.find`）：
- `any` 模式：任一关键词出现在**同一段**识别文本中即命中
- `all` 模式：所有关键词需出现在同一段文本中

## 5. 关键词表

| 屏幕 | 字段 | 关键词 | 区域 | 实测情况 |
|---|---|---|---|---|
| `run_map` | 当前层数 | `当前挑战` + `N层` | `[195,268,425,315]` | ✅ conf 0.98 |
| `run_map` | 界面锚点 | `结束挑战` | 右下按钮 | ✅ conf 高 |
| `battle_confirm` | 界面判定 | `开始对局` + `再想一想` | 整屏 any-of | ✅ conf 1.00（须 any-of，见下坑） |
| `battle_mulligan` | 界面判定 | `是否需要更换初始手牌` | `[809,507,1118,534]` | ✅ conf 0.99 |
| `battle` | 界面判定 | `第N轮`（左上） | `[114,87,196,122]` | ✅ conf 0.98 |
| `rest_node` | 选项名 | `【XX】` 括号名（广纳贤才/固本培元/养精蓄锐/积草屯粮/以逸待劳/研读兵法/稳中求进/秣马厉兵/劫营速战） | y∈[790,940] | ✅ conf 0.96~0.99，检测见 `rest.py detect_rest_options` |
| `gift` 一级 | 赠礼武将 | `XX赠礼`（y∈[740,860]） | 整屏 | ✅「樊哙」可能被截成「樊」，靠子串匹配兜住 |
| `gift` 二级 | 赠礼类型 | `信物/资助/并肩作战/武将卡/驰援` | y∈[220,780] | ✅ conf 0.9x |
| `shop` | 商品解析 | **纯数字=价格**，其同列正上方最近的**纯中文名**=商品名 | 整屏 | ✅ 解析器 `shop.py parse_shop`；⚠ 过滤「专区」标题与「5.0折」折扣标签（含数字的名字一律不要） |
| `shop` | 余额 | 右上角纯数字 | `[1620,110,1780,160]` | ✅ conf 1.00 |
| `hero_event` | 事件判别 | 描述关键词：无法打出桃/速度降为/无法打出装备牌/无法获得太平百钱/随机弃置+行动牌/天雷 | 三行 y≈335/530/715 | ✅ 标题「十常侍的蛊惑N」是专属文案不可当判据 |
| 卜卦页 | 界面判定 | `请点击卡牌完成卜卦` / `卜卦` | 整屏 | ✅（卧龙出山特有） |
| 卦象页 | 界面判定 | `请点击继续` | 底部 (928,942) | ✅ 点击后可能弹武将信息卡 |
| 武将信息弹层 | 界面判定 | `武将技能` + `武将信息` 同时在场 | 整屏 | ✅ 点 (1800,250) 关闭 |
| `battle_confirm` | ⚠ 反例 | `战役属性` | 标题区 | **美术字读成「战没属性」conf=0.88，不能当锚点** |
| `run_map` | ⚠ 反例 | `已通关` 印章 | 节点圆上 | **读成「巨通关」，且本就不识别已通关节点** |
| 泛词 | ⚠ 反例 | `商店`/`事件`/`休息` | 整屏 | **地图页顶部图例栏含这些词，作界面判定必误报**（曾把地图页判成事件/休息节点页） |

> **any-of 坑**：多关键词界面判定必须用「任一命中」，不能要求同段全含——
> 「开始对局」「再想一想」是两个独立 OCR 条目（`ocr.find` 的 `all` 语义已修正为跨条目）。

### 5.1 预期需要 OCR 的字段

| 屏幕 | 字段 | 用途 | 预期关键词/正则 |
|---|---|---|---|
| `run_map` | 当前里程 / 层数 | 判断是否达到目标层数 | `里程\D*(\d+)` |
| `run_map` | 节点类型 | 区分战斗/事件/休息节点 | `["战斗","事件","休息"]` |
| `battle` | 自动战斗标识 | 确认处于托管状态 | `["自动","托管","倍速"]` |
| `battle_result` | 胜负 | 分支处理 | 胜 `["胜利","通关"]` / 负 `["失败","阵亡","败北"]` |
| `buff_choice` | 增益文本 | 给选项打分（可选，主要靠用户判断） | 见 `policy.py` 权重表 |
| `run_settle` | 结算标识 | 判定本局结束 | `["结算","里程奖励","获得"]` |
| `popup_confirm` | 弹窗按钮 | 通用确认 | `["确定","知道了","确认","下一步"]` |

### 5.2 采集方法

```bash
# 在目标界面抓图
.venv/Scripts/python.exe run.py capture --count 2 --tag buff_choice

# 离线跑 OCR，打印全部文本与置信度
.venv/Scripts/python.exe run.py analyze --image assets/screenshots/xxx.png --ocr
```

从输出中挑选**置信度 ≥0.95 且长度短**的文本作为关键词；对数值字段改用正则。
