# 02 · 通关策略逻辑

> 本文档分两部分：**① 玩法规则与通用策略**（来自官方说明与公开攻略，用于给决策打分）；**② 自动化状态机映射**（脚本"看到什么界面 → 做什么操作"）。第二部分需在真实界面上标定后补全。

---

## 一、玩法规则（千里单骑）

| 项 | 内容 |
|---|---|
| 模式性质 | 单人肉鸽（Roguelike）闯关 PvE，三大核心战役之一 |
| 参与条件 | 拥有武将数 ≥ 16；消耗 **1 个天命令** |
| 难度 | 8 档（壹~捌），每提升 1 级敌方武将总属性 +2（随机分配）；难度决定义旗上限 |
| 地图 | **每次随机**；节点类型有 3 种 |
| 失败 | **一次机会**：阵亡或逃跑立即结算，下次重来 |
| 状态保留 | 战斗胜利后保留：武将等级、血量、手牌/手牌上限、装备、永久技能、速度 |

### 节点类型

| 节点 | 内容 | 脚本对应界面 |
|---|---|---|
| **战斗节点** | 打败全部敌人即胜；胜利后可选增益 | `battle` → `battle_result` → `buff_choice` |
| **事件节点** | 随机事件，最多 3 个选项；选择不同会导致后续事件不同 | `event_choice` |
| **休息节点** | 回复体力 / 获得牌 / 增强牌堆；结束时**有概率被"偷袭"** | `rest_node` → `buff_choice` |

### 奖励

- 每通过 1 个节点累计 **1 里程**；每 2 里程得 1 个单骑宝箱
- 宝箱奖励：单骑边框、**名将册**、军令状（名将册概率 3.62%）；对局胜利时也有概率直接获得名将册
- **义旗**：在战役商店可换形象边框、名将册、问鼎令等

## 二、通用策略（用于给选项打分）

### 2.1 增益选择优先级

公开攻略的共识排序（脚本据此给选项打"推荐分"，**最终仍由用户确认**）：

```
杀的伤害（输出核心）
  > 摸牌数 / 手牌上限（资源与续航）
  > 回复体力（血量吃紧时优先级上升）
  > 速度（后期影响先手，避免被连招带走）
  > 其它全属性增益
  规避：任何"减益"项（失去/减少/弃牌/受到额外伤害）
```

核心逻辑：后期关卡敌方数量与血量上升，**必须靠叠加"杀的伤害"快速减员**；同时前期不要把手牌打光，适当拖回合补牌。

打分实现见 `src/game/policy.py::DecisionPolicy`，关键词权重表可在 `config/settings.yaml` 的 `policy.keyword_weights` 覆盖。

> 该排序仅是**建议**。按 `decision.mode = ask`（默认），每个增益三选一都会暂停并提示推荐项，由你裁定。

### 2.2 武将选择建议（供你参考，脚本不自动选将）

| 取向 | 推荐 | 理由 |
|---|---|---|
| 高爆发/连击 | 赵云、甘宁 | 赵云出杀可过牌、闪可当杀；打出 7 张杀/闪后提升手牌上限与出杀次数 |
| 被动输出 | 项梁 | 其他角色回合开始时可对其打出一张杀 |
| 抢技能流 | 霍去病 | 「封狼居胥」重伤他人时可夺取其一个技能 |
| 邪道刷技能 | 韩非 | 「不期修古」抽 3 张武将牌选 1 技能，可刷出大量技能 |
| 续航防守 | 刘备、华佗 | 回复/减伤，延长里程 |

### 2.3 风险与撤退判断

- 千里单骑**只有一次机会**，阵亡即结算。因此"是否在血量健康时主动撤退换下一局"是**高风险决策**。
- 脚本的策略：**不主动撤退**。若你配置了目标层数，`policy.should_retreat()` 会给出建议，但该决策在 `hybrid` 模式下**强制询问**，在 `ask` 模式下同样会暂停提问。

        (暂停提问)             (暂停提问)

                        ▼

### 4.1 一局完整循环（已验证两场）

```
主页 → enter(战役→千里) → hero(选钟离眜) → 开始挑战
  └→ run_map: nodes 识别 → 选节点（规则1）
       └→ battle_confirm: 开始对局 (708,920)
            └→ battle_mulligan: 取消 (1105,622)          （规则2）
                 └→ battle: 金盘→托管，等待 ~40-60s      （规则3）
                      └→ 完胜: 空白 (960,900)            （规则4a）
                           └→ 预览: 下一步 (958,953)     （规则4b）
                                └→ 结算: 确认 (960,937)  （规则4c）
                                     └→ 赠礼: gift 规则  （规则5/6）
                                          └→ 回 run_map（下一层）
```

以下参数会影响自动化行为，建议明确（当前取保守默认）：

| 参数 | 当前默认 | 说明 |
|---|---|---|
| 本局终止条件 | 战到阵亡 / 通关 | 是否主动撤退换局 |

## 一级赠礼选人规则（2026-11-12 用户确认）

一级「请选择接受谁的赠礼？」三位候选：

1. 三人都不在三类名单 → **固定选中间**（2026-09-16 规则）。
2. 有人有类别 → 按 **信物 > 驰援 > 资助** 取最优；同类别多位按**名单枚举顺序**（gift.py 注册顺序/GUI 名单顺序）取最前者——与屏幕左右位置无关（2026-11-12 龙且/吕布案例后修正）。
3. 跨类别按 1 的类别优先级；"排前面"指**名单顺序**而非屏幕位置。
4. 二级赠礼类型继续按类别优先级表选，与选项上下位置无关。
