# 05 · 图像模板素材清单

## 1. 用途与原则

模板匹配负责识别**固定按钮、图标、界面锚点**（美术字体/图形 OCR 不可靠）。

| 项 | 值 |
|---|---|
| 存放目录 | `assets/templates/` |
| 支持子目录 | 是，如 `battle_result/continue.png` |
| 匹配算法 | `cv2.matchTemplate` + `TM_CCOEFF_NORMED` |
| 匹配阈值 | 默认 **0.86**（`settings.yaml → vision.template_threshold`） |
| 多尺度搜索 | `[0.92, 0.96, 1.0, 1.04, 1.08]` |
| 去重 | NMS，IOU 阈值 0.35 |
| 单次耗时 | 约 5–20ms |

## 4. 采集与制作方法

### 4.1 采集截图

```bash
.venv/Scripts/python.exe run.py capture --count 2 --tag <界面名>
```

### 4.2 量取坐标

```bash
# 生成 50px 细网格图，便于精确读取裁剪框
.venv/Scripts/python.exe tools/make_template.py \
    --src assets/screenshots/xxx.png --grid-only --step 50
```

### 4.3 裁剪模板

```bash
.venv/Scripts/python.exe tools/make_template.py \
    --src assets/screenshots/xxx.png \
    --box 780,980,1140,1050 \
    --name battle_result/continue
```

工具会自动：
1. 生成 `xxx_crop_preview.png`（在原图上框出裁剪区域，供复核）
2. 保存模板到 `assets/templates/battle_result/continue.png`

### 4.4 验证

```bash
# 离线跑一遍全部模板匹配，确认分数达标
.venv/Scripts/python.exe run.py analyze --image assets/screenshots/xxx.png --templates
```

命中分数建议 **≥ 0.90**；若在 0.86–0.90 之间，说明模板偏"脏"（含背景/阴影），建议重新裁剪得更聚焦。

## 5. 模板制作最佳实践

| 要点 | 说明 |
|---|---|
| **裁剪要"紧"** | 只框住目标元素本身，尽量不含大面积背景，避免背景差异导致分数下降 |
| **选特征独特的锚点** | 锚点应只在该界面出现（如标题艺术字的一角、专属图标），避免与其它界面混淆 |
| **避开动态区域** | 不要框入会变化的数字、进度条、动画区域 |
| **同元素多版本** | 若按钮在"可点/不可点"两种状态下外观不同，采集两张：`continue.png` / `continue_gray.png` |
| **尺寸适中** | 模板不宜过大（匹配慢）也不宜过小（易误匹配），建议 40×40 ~ 400×120 |
| **透明/半透明元素** | 截图为不透明 PNG，无需 alpha 通道 |

## 6. 特殊案例

### 6.1 ⚠ 别拿"图例栏"的图标当模板

地图页顶部有一行图例「战斗 · 商店 · 事件 · 休息 · 武将 · 伙伴」，图标与节点上的类型标识
**同形但不同底**：图例是深蓝灰木牌底，节点图标是米色卡底、且半透明叠在武将头像上。

实测：拿图例图标去匹配节点位置，最高分仅 **0.358**（阈值 0.86），完全不可用。

**正确做法**：从游戏截图的**真实节点**上直接裁图标 —— 跨节点分数 `1.00 / 0.90 / 0.87`，
非节点区域最高仅 `0.48`。图例图标已挪到 `assets/templates/run_map/_ref_legend/` 仅作参考。

### 6.2 ⚠ 比对窗口的边距不能抠

固定窗口 + 模板滑动比对时，**窗口必须比模板明显大一圈**。
边距不足会让模板在窗口边缘被裁掉一行像素，分数虚低（实测 node3 由 0.857 掉到 0.659），
结果贴着阈值、随机误判。`src/game/node_icon.py` 里 `ICON_MARGIN = 14`。
